# BaristaMatch app audit — September 7, 2026

Release candidate: **1.0.4**, iOS and Android. Website parity baseline: main `a54e180` (private café pricing and website account repairs). This audit records source repairs and verified checks; a source test pass is not a store approval or physical-device result.

## Repairs included

- **Authentication:** Saved account role is authoritative. New OAuth members choose a role and complete signup explicitly; email verification does not write profiles without a session. Duplicate callback exchanges share one request. Login, cancellation, verification resend and password recovery have recoverable errors. Removed the obsolete café subscription setup call.
- **Profiles:** Required-field completion includes a photo and valid private birth date. Gender stays optional and private. Both roles can explicitly control discovery visibility. Save confirms the server's returned row, preserves saved opt-outs, saves private data before public eligibility, protects uploads/drafts during navigation and retries, and restores the last saved profile on Cancel.
- **Marketplace:** Exact Florida city/ZIP search matches the website. Pagination does not discard candidates after the first hundred results. Applying to a particular job is separate from expressing interest in a café. Incoming/sent interests and application history remain reachable independently of active jobs. Job edits retain pay ranges, custom schedules and applicants; cafés can pause and reopen posts.
- **Messages:** Conversations, drafts and in-flight requests are tied to their account and recipient. Stable client message IDs make uncertain retries idempotent. Unread notifications use the existing application receipts and new discovery receipts, with matching read acknowledgements. A paused job no longer breaks a previously matched conversation. The metadata endpoint checks membership and blocks before returning café identity.
- **Home and notifications:** Dashboard counts include job applications, sent interests, both match types and unread conversations. Taps lead to the relevant lists. Push routes are validated and preserve conversation kind/job ID. Notification permission is requested from a user-triggered Settings control; denied permission is reported accurately.
- **Settings and account lifecycle:** Café plans stay hidden until the saved café role is verified, and hide on sign-out/account change. Profile and billing errors offer retry instead of false active status. Password changes use the reviewed account's captured token. Deletion confirmations retain their original account ID. A serialized auth-storage adapter prevents cleanup from erasing a different account signing in concurrently. API and Supabase requests have deadlines.
- **Traffic and dependencies:** Eight live row-security identity checks now run once per statement, and discovery messages have a sender index. Permissions and billing rules are unchanged. Decoder/PostCSS/UUID vulnerabilities received compatible fixes; Expo/React Native majors were retained. The unpatched image parser is mitigated by rejecting affected build formats in both Metro processes. See [dependency evidence](../mobile/DEPENDENCY_SECURITY.md).
